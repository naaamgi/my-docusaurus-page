파일 업로드 취약점

1. 공격 시나리오 전체 흐름​

파일 업로드 취약점의 궁극적 목표는 단순히 파일을 올리는 것이 아니라, 서버에서 명령어를 실행하는 것.

웹셸 업로드 → 실행 경로 찾기 → 명령어 실행 → 서버 내부 탐색 → 소스코드/중요 정보 탈취

2. 파일 선택 시점에 업로드되는 케이스​

파일을 선택하는 순간 바로 업로드되는 경우가 있다. Burp Suite 인터셉트를 켜고 파일을 선택했을 때 요청이 날아가는지 확인해야 한다.

3. 서버 저장 시 랜덤 파일명 생성​

서버가 업로드된 파일의 이름을 랜덤으로 바꿔서 저장하는 경우, 실행할 수 있는 경로를 찾아야 한다.

경로 찾기 방법:

  • 업로드 응답에서 파일 경로 확인
  • 게시판에 첨부된 이미지를 우클릭 → "이미지 주소 복사"
  • 소스코드 분석으로 저장 경로 유추
  • 디렉토리 구조 유추 (예: /upload/, /files/, /attachments/)

4. JSP vs JSPX​

구분JSPJSPX
문법기본 JSP 태그 (<% %>)XML 기반 문법
용도일반적인 서버사이드 스크립팅XML 호환 환경에서 사용
우회 활용.jsp 차단 시 기본 시도.jsp 차단 시 우회 확장자로 활용

웹셸 핵심 코드:

Runtime.getRuntime().exec(request.getParameter("cmd"))

5. 확장자 필터링 우회​

.jsp 확장자가 차단될 때 시도할 수 있는 확장자:

  • .jspx — XML 기반 JSP
  • .jsp3, .jspv — 서버 설정에 따라 실행될 수 있는 변형
  • 대소문자 혼용: .JsP, .JSP

6. 취약점 진단 vs 모의해킹 관점​

관점판단 기준
취약점 진단위험 확장자 파일이 업로드 가능하면 취약 (실행 여부 무관)
모의해킹업로드 + 실행까지 성공해야 공격 성공

진단 시에는 .jsp 파일이 올라가기만 해도 취약점으로 보고한다.

7. JavaScript 파일 업로드 필터링 우회​

프론트엔드에서 확장자를 JavaScript로 검증하는 경우:

if (!/\.(gif|jpg|jpeg|png)$/i.test(filename)) {
    alert("gif, jpg 파일만 선택해주세요");
    return;
}

우회 방법:

  1. Burp Suite에서 JS 파일 인터셉트
  2. if 조건의 느낌표(!) 삭제 → 조건 반전
  3. 또는 if문 전체 삭제

8. Burp Suite 인터셉트 고급 설정​

JS 파일 인터셉트 설정​

  1. Proxy → Settings → Intercept Client Requests
  2. 기본 규칙의 |js$|css$|png$|... 부분 삭제

캐시 방지 (Match & Replace)​

항목설정 내용
If-Modified-SinceMatch & Replace로 해당 헤더 제거
If-None-MatchMatch & Replace로 해당 헤더 제거

응답 인터셉트 설정​

Proxy → Settings → Intercept Server Responses 활성화

9. 대응 방안​

  • 백엔드에서 확장자 검증 (화이트리스트 방식)
  • 업로드 디렉토리 실행 권한 제거
  • 파일명 랜덤화 + 원본 파일명은 DB에 저장
  • 불필요한 개발 파일 삭제 (.bak, .old, test.php 등)

트러블슈팅 체크리스트​

  • 서버 측 확장자 검증이 화이트리스트 방식인가?
  • 업로드 디렉토리에 실행 권한이 제거되어 있는가?
  • 파일명이 랜덤화되어 저장되는가?
  • 업로드 응답에 실제 저장 경로가 노출되지 않는가?
  • Content-Type 검증이 서버 측에서 이루어지는가?
  • 불필요한 개발 파일(.bak, .old 등)이 제거되어 있는가?
